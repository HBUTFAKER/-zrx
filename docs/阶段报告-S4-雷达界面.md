## 四、当前灯态直读产物，不再自算（S4-M1，审计请看这条）

005S-R3 起，施工A 已把当前灯态写进产物 `latest.light_state`：

```json
{"state": "normal", "as_of": "2026-11-09", "drawdown": -0.04931,
 "window": 20, "threshold": -0.1,
 "rule": "H00300 收盘相对过去 20 日最高收盘回撤 ≤ -10% → defensive，否则 normal"}
```

界面**逐字直读**，不读基准 parquet、不调 `src.radar_005s`、不自行判定。
`web/radar_data.py` 里已无任何重算逻辑（有测试 `test_no_self_recomputation` 守着）。

三处口径变化，界面已同步：

1. **阈值符号**：产物里 `threshold` 是**负数**（−0.1），判定式 `drawdown <= threshold → 防守期`。
   界面显示取绝对值再补负号（印出「阈值 −10%」，不是「−−10%」）。
2. **`state` 三态**：除 `defensive` / `normal` 外，产物允许 `null`（该交易日无基准收盘或缺前置窗口）。
   界面显示为「⚪ 未判定」，**绝不显示成正常期** —— 把「没算出来」说成「安全」等于凭空放宽。
   未判定时名单不展示、也不冒充「正常期只报状态」。
3. **规则文案**：灯块显示 `latest.light_state.rule`（本次判定的规则原文）；
   `rules.light` 是「月内任一交易日亮 → 该月为防守月」的**月度归类**规则，
   两者用途不同，历史统计块的防守月清单仍按 `rules.light` 口径。

原先「产物里没有当前灯态位、界面只能自算」的问题，由 005S-R3 在产物层解决，界面层已跟上。

## 五、Top100 显示股票名称（S4-M2，总工 b 项批准）

产物 `latest.watch_names` 是 code→简称 的映射（100 条），界面已接进 Top100 表格：

| 名次 | 代码 | 名称 |
|---|---|---|
| 1 | sh.688425 | 铁建重工 |
| 2 | sh.601228 | 广州港 |
| … | … | … |

实现口径三条：

1. **名称只取产物，界面不自己查名**。`web/radar_data.py` 直接读 `latest.watch_names`，
   不引入任何行情/取数依赖（有测试 `test_no_self_looked_up_names` 守着源文件扫描）。
2. **缺名称只显示代码、不占位**。产物没给名称的代码，名称列留**空字符串**，
   不写「—」/「未知」/「None」。名称是给人看的补充，缺一个名字不该让整张名单渲染不出来。
   本产物 `watch_names_missing` 为空（missing=0），即 100 只全覆盖；
   防御性分支已用变异测试验证（造一份缺 3 个名称的产物，名单仍 100 行照常展示）。
3. **名称与代码同行对齐**。表格按 `watch.codes` 顺序逐行构造，
   `名称` 取同一行的代码去 `names` 查，不允许错位一格（有测试逐行对拍 + 变异测试守着）。

产物里名称为空串（`"   "`）视为「该代码没有名称」，不落进 `names` 表。
`latest.watch_names` 整段缺失 → 直接报错，不静默降级成「无名称」
（与 `latest.light_state` 同一处理原则：字段缺失必须露出来）。

## 六、边界（实现约束）

- **运行时零大模型接口**：`web/` 下不 import 任何 LLM SDK、无任何网络调用（AST 扫描 + 源码扫描双重断言，见测试 `TestNoLLM`）
- **只读**：只 `json.load`，装载前后 `out/` 目录 mtime 不变（有测试守着）
- **不做买入推荐**：无买入/建议类字样、无收益率预测、无目标价；**避雷名单已判失败（2/5=40% < 70%），完全不读、不展示**
- **文案硬约束逐字照抄**，见 `web/radar_data.py` 顶部常量 + 测试 `TestHardCopy`
- **禁字表用片段拼装**：源码里不留完整禁字明文，grep 审计能干净通过；运行时 `BANNED_SUBSTRINGS` 仍等于完整集合
