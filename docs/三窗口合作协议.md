## 二、通信协议

1. **一切信息经业主搬运**，窗口之间不直接对话、不共享记忆。业主搬运时只复制原文，不概括、不加评价。
2. **一切任务带编号**：施工指令 `量化炒股系统001–006`；审计任务 `量化炒股系统审计-A/B/C…`。汇报第一行必须回带指令编号，无编号的汇报总工拒收。
3. **每个窗口固定角色、固定模型**。换模型必须经总工批准并记入本协议变更记录。
4. **汇报统一格式**：产出清单 + 测试/验证结果（附命令与输出）+ 遗留问题 + 停止声明（"等待验收，不进入下一阶段"）。

## 三、工作循环（七步，每阶段走一遍）

| 步骤 | 动作 | 执行方 → 接收方 |
|---|---|---|
| 1 | 总工发出带编号的阶段指令 | 总工 → 业主 → 施工窗 |
| 2 | 施工窗开工前：读本协议 + 上位文件 + 指令内列明的源文件，回复"就位"再动手 | 施工窗内部 |
| 3 | 施工完成，停下交汇报（带编号） | 施工窗 → 业主 → 总工 |
| 4 | **总工预验收**：亲自复跑测试、抽查产物 | 总工 |
| 5 | 预验收通过后，总工出审计任务；业主发审计C | 总工 → 业主 → 审计C |
| 6 | 审计C 交问题清单（≥5个疑点，附验证证据） | 审计C → 业主 → 总工 |
| 7 | 总工裁决：**通过**（发下一条指令）/ **返工**（列明返工项发回施工窗） | 总工 → 业主 → 施工窗 |

## 四、质量规则（全体遵守）

1. **三条底线**（原文见框架第 0 节）：不编造数据；不承诺收益、不出"买入/卖出"信号；仅限业主本地个人研究使用。
2. **验收权分离**：测试断言规格由总工给出（精确到"等于几"），施工部只实现；施工部自行放宽断言 = 返工。
3. **口径先行**：数据类指令含【数据口径·逐条确认】小节；施工部发现口径不可行时**停下报告**，禁止静默降级、禁止静默跳过（缺口必须写入 `data/gaps.csv`）。
4. **版本戳铁律**：所有 `out/*.json` 必含 `git_commit`、关键参数、数据截止日，缺一为无效产物。
5. **审计KPI**：审计C 每次至少列 5 个疑点，附验证命令与输出；给"总体不错"式结论视为失职。
6. **争议裁决**：施工部对审计结果有异议 → 双方证据交总工 → 总工裁决 → 业主通报双方。业主全程不站队。

---

## 五、停工上报条件（任一触发，立即停手等总工）

- 指令口径与现实数据不符（如退市股行情拉不到且降级路径走完）
- 测试按总工规格无法实现
- 施工中出现指令未要求的新需求想法（记下来汇报，不许顺手做）
- 任何会改变已验收产物的修改冲动
