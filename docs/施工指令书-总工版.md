## 0. 使用规则（业主必读，30 秒）

1. **串行为主**：S0→S1→S2→S3→S5 必须按顺序，前一阶段没验收不过，不发下一条。只有 S4（界面）可以和 S3 并行开第二个窗口。
2. **验收循环**：施工窗口每完成一阶段会停下来汇报 → 你把汇报结果带回来找总工（本会话）验收 → 通过后我给下一条指令词。**不要让施工窗口自己一路做完。**
3. **防跑偏**：如果施工窗口开始加框架文档里没有的功能（自动交易、实时行情、AI 预测涨跌），立即叫停。
4. 每阶段完成后，施工窗口必须**本地 git commit**（GitHub 暂缓：业主回家后建私有仓库 `quant-app`，届时一次性推送全部提交，提交历史完整可推）。
5. **发指令前看开头标注**：每条指令词第一行是【窗口A/窗口B｜模型：xxx】——发给对应窗口，并确认该窗口当前选用的模型与标注一致。换模型必须回报总工。
6. **开工程序**：现在就可以把 S0 发给窗口A（模型选 glm5.3flash）。
7. **铁律（外部评审采纳）**：LLM 只在离线批处理（即施工期写代码）中参与；**运行时的 App 不调用任何大模型接口**，界面只读确定性代码的产物；所有 out/*.json 必须携带三个字段——git_commit（产出代码的提交哈希）、关键参数、数据截止日——缺一视为无效产物。
8. **验收权分离（v1.3 采纳外部审计意见）**：验收测试的**断言规格由总工给出**（精确到"等于几"），施工部只实现、不得自行放宽；总工在验收点亲自复跑全部测试；另设**审计部（窗口C）**，每阶段交付后对新窗口发起对抗性审查（模板见第 6 节），审计报告交总工裁决。
9. **口径先行**：每个数据相关指令必须包含【数据口径·逐条确认】小节，施工部不得自行变通；发现口径不可行，停下来报告，不许静默降级。

### 三窗协作规则（谁在什么时候干什么）
